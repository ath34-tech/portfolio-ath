Ath Tripathi builds the systems around the models

Routing gateways, real-time voice agents, a local desktop assistant and an inference lab. Ath works the whole path, from inference to interface.

By the Editorial Desk · Applied AI & LLM Engineer · B.Tech CSE (AI)

A lot of AI demos never get past the notebook. Ath Tripathi keeps going until someone can actually use what he built. He builds LLM products end to end: the router that picks which model answers, the backend that streams the tokens, the voice pipeline that has to stop talking when a twelve-year-old interrupts it, and the interface on top.

His builds so far: Pixie, a desktop agent that launched on Product Hunt. RouteLLMESH, an OpenAI-compatible router. Bodh AI, a real-time voice interviewer. KV Cache Lab, a tool for seeing what inference really costs. Dexa, a multi-agent ML copilot for the terminal. He has also turned research papers like ReTree and ATLAS into running code.

“I'd rather show you what I built, where it was hard, and what changed than give you a list of buzzwords.”

Most of his interest sits in the unglamorous middle of the stack: prefill and decode, time-to-first-token, KV-cache memory, tool selection, conversation state. He learns by building, measures before he makes a claim, and writes it all up. That's 74 tutorials, 30K+ Medium views, and guest bylines on the Twilio, Strapi and Webiny blogs.

Now accepting offers for Applied AI, LLM / Agent, AI Product and AI-infrastructure backend roles, especially at early-stage teams where one engineer owns a feature from start to finish.

A1 · Product · Desktop

Pixie: an AI agent that lives on your own machine

A local productivity agent that can use a model running on your laptop or a hosted one, through the same interface.

Pixie is a Tauri + React + Vite desktop app with a Python backend. Ollama provides local models, and Groq, GPT and Gemini sit behind the same provider layer, so changing the model doesn't mean rebuilding the app.

Tool use works in two steps. Pixie first picks a tool by reading the tool descriptions, then builds that tool's parameters. Conversation and memory controls stay with the user.

The hard partMaking local models approachable. Installing Ollama and pulling a model is easy for a developer and a wall for everyone else, so onboarding turned into an engineering problem of its own.

A2 · Infrastructure

RouteLLMESH: one endpoint, many models behind it

A FastAPI gateway that speaks the OpenAI API. Send model:auto and it chooses a provider and model based on cost and task complexity.

client→/v1/chat→router→Groq · …

PostgreSQL 17 and Redis hold the gateway's state. LangSmith traces each routing decision, so you can see why a request went where it did.

A3 · Voice · Real-time

Bodh AI: a voice interviewer that knows when to be quiet

Spoken interviews in Hindi and Hinglish for Grade 7–8 students. Students join with a school code and student ID, so there's no login to remember.

mic · 48 kHz→LiveKit→Deepgram→LLM→TTS

The interview state tracks confidence, evidence and completed, and follow-up questions are chosen from it. The hard bugs: barge-in, awkward pauses, repeated questions, and hanging up too early on “bye.” The design target is a sub-second turn. It's a goal, not a measured benchmark.

  • FastAPI
  • Deepgram
  • Gemini 3.1 Flash-Lite

KV Cache Lab: what does a long conversation actually cost?

A local-first LLM chat app: Ollama inference with a live dashboard for TTFT, TPOT and tokens/s, next to a theoretical KV-cache estimator. The point is to connect the runtime numbers to the math behind them. Try the estimator below with Qwen3 8B's real config.

A7 · Agents · Developer tooling

Dexa: a terminal-first agentic copilot for ML engineers

Point it at a dataset and talk to it from the terminal. A team of agents profiles the data, flags missing values, skew, outliers, imbalance and leakage, suggests preprocessing, models and metrics, and diagnoses problems like overfitting.

query→understand→plan→execute→reflect→respond

The agents run as a LangGraph state machine. After every step, a Reflection agent decides whether to continue, replan or stop. Dexa uses deterministic tools first and falls back to generated Python only in a controlled executor.
